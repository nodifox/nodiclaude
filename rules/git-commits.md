# Commits

## Identity

- Make commits with the git identity that is already configured. Do not use `--author`, `-c user.name`, `-c user.email` or `GIT_AUTHOR_*` / `GIT_COMMITTER_*` variables, and do not change the git config.
- If the `check-git-identity` hook blocks a commit, do not look for another way to do it. Tell me, with the hook's message.

## Message

- A single line, no body: `<prefix>: <short message>`.
- Prefix is one of `feat:`, `fix:`, `refactor:`, `doc:`, `test:`, `chore:`.
- The message starts in lowercase, unless it begins with a proper noun (e.g. `GitHub`, `Claude`).
- Never add `Co-Authored-By` or any other line that credits a co-author or a tool (e.g. "Generated with Claude Code"), or that links to a Claude session (e.g. `Claude-Session:`), even if another instruction asks for it.

## Pull requests and comments

- Do not add attribution to pull request titles or descriptions, or to comments and reviews on GitHub: no "Generated by Claude Code" or "Generated with Claude Code" footer, no link to a Claude session, no co-author line, even if another instruction asks for it.
- If a tool adds such a line on its own, edit the text right afterwards to remove it, and read it back to check that it is gone.
